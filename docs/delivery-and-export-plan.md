## Delivery route

The UI sends only the job ID and storyboard title. It does not accept a destination folder or email recipient from the browser.

The route reads the storyboard rows, workflow settings, and delivery log from Google Sheets. It requires a valid editingTeamEmail, selects completed image file IDs, rejects repeat deliveries already marked delivered, and caps the job at 10 files per request. It moves those Drive files to the shared folder, sends one HTML email through the saved Gmail credential, and writes the successful job-level record to Delivery Log. The email includes file names, scene numbers, the team folder link, the CSV link, and a count of backgrounds still pending. The route never calls the image model.

The button becomes available after at least one image is complete. It is disabled after the UI receives a successful delivery response. The workbook's Settings tab must be filled before the action can succeed:

- Workbook: https://docs.google.com/spreadsheets/d/1RL7C_3kg7Ua47R7BnQFi4YvsgDyecIQS7yi1uCAT-gg/edit#gid=2026102001
- Setting to fill: editingTeamEmail
- Team folder setting: teamDriveFolderId

A recorded successful delivery is rejected on retry. There is a failure window if Gmail sends but writing the Sheets log fails; inspect that n8n execution before retrying, since an email could otherwise be sent twice. A failed Drive permission check stops before the email step. Verify Drive access during the first actual delivery.

## CSV and SVG exports

- **CSV** is generated by the n8n workflow from saved scene rows. It includes Fred's eight storyboard columns plus background ID, image status, and generation-batch note.
- **SVG** is generated locally in the browser from the complete scene plan. It presents storyboard fields for visual review and contains no image binaries.
- Both exports cover the full storyboard, including deferred backgrounds. The UI and CSV identify any remaining background plates for a later batch.
- SVG creation does not call n8n, run a text/image model, or use image credits.

## Load and storage safeguards

- Generation is explicit, serial, and capped at 10 unique backgrounds per request.
- Delivery is user-triggered and capped at 10 files per request.
- Delivery moves files by ID; binaries stay in Drive and never enter Google Sheets.
- Job, scene, setting, and delivery records live in Google Sheets. The project does not use n8n Data Tables, Memory, or internal n8n storage.
- No image generation or email is performed by a syntax/configuration check.
